# 吃药酒馆设计

日期：2026-10-26

## 目标

把 SillyTavern（下称「酒馆」）打包成手机 App：后端和界面在同一个 App 里，App 在前台时后端不会被系统杀掉。
要能照常安装扩展和服务端插件；每次启动检查酒馆新版本并自动更新。App 公开分享给其他人使用。

本期只做安卓。iOS 是第二期，本文只定方向（见第八节）。

## 已定决策

| 事项 | 决定 |
|---|---|
| 名称 | 显示名「吃药酒馆」，包名 `xyz.chiyao.tavern`，仓库 `chiyao-tavern` |
| 许可证 | 整个仓库 AGPL-3.0，GitHub 公开。「关于」页注明非官方、基于 SillyTavern，附酒馆许可证与源码链接 |
| 保活要求 | App 在前台时不断即可。另挂一个前台服务（常驻通知），短暂切出去不断；不做吃药机式的后台保活 |
| 架构 | 发布版只支持 arm64-v8a；调试版额外带 x86_64，供模拟器测试 |
| 酒馆来源 | GitHub Actions 定时打包「酒馆 + node_modules」并发布到 Releases，App 下载现成的包（方案二） |
| 自动更新 | 酒馆本体每次冷启动检查并自动更新；外壳有新版时提示，由用户确认安装 |
| 扩展 | 不自动更新；酒馆自带的「更新全部扩展」照常可用 |
| 数据迁移 | App 内从 zip 导入；同时提供导出 |

## 一、整体结构

| 部分 | 内容 |
|---|---|
| 外壳（Kotlin） | 全屏 WebView、前台服务、启动页（检查更新、下载、启动进度）、设置页（镜像、导入导出、插件管理、日志、关于） |
| 自带工具 | Node 24 arm64（沿用吃药机 `tools/android` 的编译脚本）、git（CI 里用 NDK 编译，带 https 和 `git-remote-https`）、npm（Node 自带，`node npm-cli.js` 调用） |
| 酒馆包 | CI 打好的 `酒馆 + node_modules` 压缩包 |

### 启动流程

1. 读取 `latest.json`（经下载源设置），超时 5 秒。比本机新就下载、校验 sha256、解压到 `files/st/<版本>/`。启动页显示进度，并提供「跳过，这次先用旧版」。
2. 准备运行目录：在版本目录里建立指向持久目录的链接（见下表），合并 `config.yaml`。
3. 以子进程启动：`node server.js --listen false --port <端口> --dataRoot files/data --configPath files/config.yaml`。环境变量设置 `PATH`（含自带 git、node）、`HOME`、`GIT_EXEC_PATH`、`GIT_TEMPLATE_DIR`、`GIT_SSL_CAINFO`（自带证书文件）。
4. 端口可连后，WebView 打开 `http://127.0.0.1:<端口>`。
5. 新版本 30 秒内端口不通或进程退出：切回上一个可用版本启动，提示「新版本启动失败，已回退到 x.y.z」，并把该版本标记为坏版本，不再自动尝试。
6. 没网或下载失败：直接用本机现有版本启动。本机没有任何版本时，停在启动页并给出重试和镜像设置入口。

### 目录

| 内容 | 位置 | 说明 |
|---|---|---|
| 酒馆包 | `files/st/<版本>/` | 保留当前与上一个可用版本 |
| 用户数据 | `files/data/` | `--dataRoot` |
| 配置 | `files/config.yaml` | 首次由默认配置生成；之后只补新增项，不覆盖已有值 |
| 服务端插件 | `files/plugins/` | 版本目录内 `plugins` 链接到此 |
| 停用的插件 | `files/plugins-disabled/` | |
| 全局扩展 | `files/third-party/` | 版本目录内 `public/scripts/extensions/third-party` 链接到此 |
| 日志 | `files/logs/` | 保留最近 5 次运行 |
| 工具 | 随 APK 的 native lib 目录 | Node、git 以 `lib*.so` 命名放进 `jniLibs`，安装后可执行 |

### 强制配置

不管 `config.yaml` 里怎么写，以下几项以外壳为准：`listen: false`、端口、`whitelistMode`（只放行 127.0.0.1）。
端口默认固定 8000，不随机：酒馆部分设置存在 localStorage，按「地址+端口」隔离，端口变了就丢。端口被占用时提示，设置页可改。

## 二、扩展与服务端插件

### 扩展

酒馆的「安装扩展」「更新全部扩展」不改代码，依赖第一节里的 git 环境变量。
设置页开关「GitHub 克隆走镜像」：写入 `HOME/.gitconfig` 的 `url.<镜像>.insteadOf`。

### 服务端插件管理页

| 操作 | 做法 |
|---|---|
| 添加 | 填 git 地址克隆到 `files/plugins/<名字>`，或从 zip 导入；有 `package.json` 时跑 `npm install --omit=dev` |
| 启用 / 停用 | 在 `plugins/` 与 `plugins-disabled/` 之间移动 |
| 更新 | 单个插件 `git pull` 后重跑 `npm install` |
| 删除 | 删除文件夹 |
| 生效 | 首次安装插件时把 `enableServerPlugins` 设为 true；改动后提示「重启酒馆生效」，点击后重启 Node 并刷新页面 |

### 原生模块

依次处理：

1. 包本身发布了 `android-arm64` 预编译版的，npm 按平台自动选用。
2. 替换表：`npm install` 时通过 `overrides` 自动替换为纯 JS / WASM 实现。首批：

   | 原生包 | 替代 |
   |---|---|
   | `sharp` | `@img/sharp-wasm32` |
   | `better-sqlite3`、`sqlite3` | `node:sqlite` 适配层或 `sql.js` |
   | `bcrypt` | `bcryptjs` |
   | `canvas` | `@napi-rs/canvas` |

3. 仍失败且原因是 node-gyp 编译：提示「这个插件需要编译原生模块，手机上不支持」，并显示关键报错。

不做：CI 预编译插件、手机上带编译工具链。

## 三、更新

### 酒馆包（CI）

GitHub Actions 每 6 小时检查官方 `release` 分支。有新版本时：

1. 检出该版本，Linux 上 `npm ci --omit=dev`。
2. 冒烟：Node 24 启动酒馆，请求首页返回 200。
3. 压缩，发布到 Releases，标签 `st-<酒馆版本>-<构建号>`。
4. 更新 `latest.json`：

```json
{
  "st": { "version": "1.18.0", "build": 1, "url": "...", "sha256": "...", "size": 0, "minShell": 1 },
  "shell": { "versionCode": 1, "versionName": "1.0.0", "url": "...", "sha256": "...", "notes": "..." }
}
```

前提：酒馆依赖全为纯 JS，Linux 上装的 `node_modules` 能直接在安卓上用。实现计划第一步核实；有原生依赖则改为 CI 里用 NDK 交叉编译那几个。

### 外壳

冷启动时同一份 `latest.json` 里外壳版本更高：弹窗显示版本号和说明，「更新」下载 APK 并调起系统安装，「以后再说」关闭。
酒馆包的 `minShell` 高于当前外壳时，不装该包，继续用现有版本，并提示先更新外壳。

设置页「检查更新」按钮，显示外壳版本和酒馆版本。

### 镜像

| 设置 | 选项 |
|---|---|
| 下载源 | GitHub 直连 / 自定义加速前缀 |
| npm 源 | 官方 / npmmirror |
| git 克隆镜像 | 开关 + 地址 |

默认直连；连不上时提示去设置镜像。不内置公共加速地址。

## 四、首次启动、导入与导出

1. 欢迎页说明需要下载酒馆（显示大小），可进镜像设置。
2. 下载完成后二选一：全新开始 / 从备份导入。
3. 启动酒馆。

**导入：** 系统文件选择器选 zip，识别三种结构：完整 SillyTavern 目录、`data/`、`default-user/`。zip 内的 `plugins/`、`third-party/`、`config.yaml` 一并导入；`config.yaml` 合并普通设置，强制配置项不导入。覆盖前把当前数据自动备份为 zip。

**导出：** 数据、插件、全局扩展、配置打成 zip，存入「下载」。

## 五、WebView

| 项 | 做法 |
|---|---|
| 上传文件 | 实现 `onShowFileChooser` |
| 下载 | 接管 blob / data 链接（注入脚本把内容交给外壳），存入「下载」 |
| 返回键 | 能后退就后退，否则 `moveTaskToBack` |
| 外链 | 非 `127.0.0.1` 的链接用系统浏览器打开 |
| 渲染进程崩溃 | `onRenderProcessGone` 后重建 WebView 并重新加载 |

## 六、出错处理

- 启动页实时显示酒馆输出最后几十行；失败时停留，提供「重试」「复制日志」「回退版本」。
- 运行中 Node 意外退出：页面上盖一层「酒馆意外退出」，可「重启」「查看日志」。
- 设置页一键复制最近日志。

## 七、测试

| 层 | 内容 |
|---|---|
| 单元测试（JVM） | 版本比较、清单解析、回退与坏版本标记、config 合并与强制项、导入 zip 结构识别、替换表 |
| CI | 酒馆包在 Linux Node 24 上冒烟；编译 APK |
| 模拟器（调试版 x86_64） | 首次下载、启动、装扩展、更新全部扩展、装服务端插件、导入导出、更新、回退 |
| 真机 | 给出检查清单，由用户验证；汇报里写明哪些未在真机验证 |

## 八、iOS 第二期（方向）

- 第 0 步：模拟器里用 nodejs-mobile（Node 18）跑酒馆 1.18，复用吃药机的 fetch、Intl、正则补丁。不通先告知再定。
- git：iOS 酒馆包给扩展相关接口打补丁，改用 isomorphic-git。
- 服务端插件：npm 能否运行由第 0 步验证；不行则只支持导入带 `node_modules` 的 zip。原生模块只能用纯 JS 替代（无 WASM）。
- 保活：只保证前台运行。

## 不做

- 后台长期保活（吃药机式）
- 扩展自动更新
- 32 位安卓
- 手机上编译原生模块
- iOS 审核相关的适配
